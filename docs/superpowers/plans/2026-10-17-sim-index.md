# SimIndex (World index) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the sim's per-tick derived structures (spatial hash, id→rock map, ship stats) off module-level/throwaway state into one session-owned `SimIndex` threaded through `tick`.

**Architecture:** A new `src/sim/index.ts` defines `SimIndex`, owning a `SpatialHash<Rock>`, a `Map<number, Rock>` and a `Map<number, ShipStats>`, and rebuilding all three in place (`clear()` + refill) via `rebuild(state)`. `tick` takes the index as a required 4th argument; `TickCtx` carries only `index` instead of three structures; `GameSession` owns the index and clears it when the running game is swapped. Import direction stays acyclic: `index.ts → ships.ts → data/*`, `update.ts → index.ts`.

**Tech Stack:** TypeScript, Three.js, Vite, vitest, oxlint/oxfmt

**Spec:** `docs/superpowers/specs/2026-10-17-sim-index-design.md` (branch `refactor/sim-index`)

## Global Constraints

Copied from the spec's Goals / Non-goals / Risks (lines 36–53, 227–251):

- **No module-level mutable state in `sim/`.** The `const rockHash = new SpatialHash<Rock>(128)` singleton in `update.ts` must be deleted.
- **`SimIndex` is transient and never serialized.** `GameState` stays plain JSON; `SimIndex` does not touch the save format.
- **No save-format change.**
- **Do not change `applyCommands`** — it is also called while paused and needs no index.
- **Out of scope:** **#16** (`src/render/shipView.ts` ~line 199 builds its own `new Map(run.rocks.map(...))` every frame) and **#18** (incremental `SpatialHash` insert/remove; `SimIndex.rebuild` uses the existing full `rebuild()`).

## Review Focus

Failure modes the spec implies that the tasks' obvious assertions do **not** directly exercise, most-likely-first. Each has a test in its owning task; a `tick` call site missed in a script rather than `src/` (`scripts/harness.ts`) is instead caught by the compiler (Task 2's `npm run typecheck`, spec 229–231).

1. **A session that swaps games and is never ticked again still holds the old run's rocks.** `rebuild` runs every tick, so only the `clear()` path releases them; it bites a paused session left open. **Owning task:** Task 3 asserts emptiness after `load`/`newGame` (spec 147–153).
2. **`stats` goes stale after a mid-tick refit / perk change.** The spec rejects lazy invalidation, but only mutating a stat source and re-`rebuild`ing proves the recompute is real, not a one-shot cache. **Owning task:** Task 1 (spec 232–238).
3. **Interleaving two games in one process.** Already true today; the test is a regression guard, not new capability. **Owning task:** Task 4 (spec 196–207).
4. **Determinism drift.** Seed replay must stay byte-identical. **Owning task:** Task 2 keeps the existing `determinism` test green through the signature change.

**Interfaces:**

- Produces: `class SimIndex { readonly rockHash: SpatialHash<Rock>; readonly rockById: Map<number, Rock>; readonly stats: Map<number, ShipStats>; rebuild(state: GameState): void; clear(): void }`.

- [ ] **Step 1: Write the failing test** in `tests/index.test.ts`.

```ts
import { describe, expect, it } from 'vitest';
import { newGame } from '../src/sim/create';
import { SimIndex } from '../src/sim/index';

describe('SimIndex', () => {
  it('rebuild reuses the same Map and hash instances', () => {
    const index = new SimIndex();
    const hash = index.rockHash;
    const byId = index.rockById;
    const stats = index.stats;
    index.rebuild(newGame(1));
    expect(index.rockHash).toBe(hash);
    expect(index.rockById).toBe(byId);
    expect(index.stats).toBe(stats);
    expect(index.rockById.size).toBeGreaterThan(0);
  });

  it('clear empties all three structures', () => {
    const index = new SimIndex();
    index.rebuild(newGame(1));
    expect(index.rockById.size).toBeGreaterThan(0);
    expect(index.stats.size).toBeGreaterThan(0);
    let hits = 0;
    index.rockHash.query({ x: 0, z: 0 }, 1e9, () => { hits++; });
    expect(hits).toBeGreaterThan(0);
    index.clear();
    expect(index.rockById.size).toBe(0);
    expect(index.stats.size).toBe(0);
    hits = 0;
    index.rockHash.query({ x: 0, z: 0 }, 1e9, () => { hits++; });
    expect(hits).toBe(0);
  });

  it('rebuild recomputes stats after a perked change (no stale cache)', () => {
    // Spec 232-238: stats are rebuilt every tick, not invalidated lazily.
    const state = newGame(13);
    const index = new SimIndex();
    index.rebuild(state);
    const ship = state.run.ships[0]!;
    const before = index.stats.get(ship.id)!.speed;
    state.profile.perks.thrust += 1; // ships.ts: speed *= 1 + 0.08 * thrust
    index.rebuild(state);
    expect(index.stats.get(ship.id)!.speed).toBeCloseTo(before * 1.08);
  });
});
```

Spec values: `thrust` multiplies speed by `1 + 0.08 * thrust` (`src/sim/ships.ts` line 36); seeds `1` and `13` give states with rocks and at least one ship.

## Task 4: Two-games interleave regression + bench record

**Files:** Modify `tests/sim.test.ts` (add the test; no `src/` change). The bench output goes in the PR description, not a file.

**Interfaces:**
- Consumes: `tick`, `SimIndex`, `newGame`, `serialize`.
- Produces: nothing (test only).

- [ ] **Step 1: Write the test** in `tests/sim.test.ts`.

```ts
it('ticks two games independently when interleaved', () => {
  const DT = 1 / 60;
  const input = { thrust: { x: 0, z: 0 }, commands: [] as Command[] };
  const a1 = newGame(101), a2 = newGame(202); // interleaved pair
  const b1 = newGame(101), b2 = newGame(202); // sequential pair, same seeds
  const i1 = new SimIndex(), i2 = new SimIndex();
  const j1 = new SimIndex(), j2 = new SimIndex();
  for (let t = 0; t < 10; t += DT) { tick(a1, DT, input, i1); tick(a2, DT, input, i2); }
  for (let t = 0; t < 10; t += DT) tick(b1, DT, input, j1);
  for (let t = 0; t < 10; t += DT) tick(b2, DT, input, j2);
  expect(serialize(a1)).toEqual(serialize(b1));
  expect(serialize(a2)).toEqual(serialize(b2));
});
```

- [ ] **Step 2: Do NOT expect a failure — this is a regression guard.** Per the spec's honesty caveat (spec 196–207), interleaving two games already worked before this change (the old `rockHash` was rebuilt from each tick's own state, and JS is single-threaded). There is no red step to observe, and stashing Tasks 1–3 would not even compile this test because the pre-change `tick` has a different arity. Record in the PR that it **passes before and after** and is a guard, not evidence of new capability. Run `npx vitest run tests/sim.test.ts`. Expected: PASS (all tests, including `determinism`).
